# Archive formats

Which interchange format we ask a publisher for, which of them this repo can
actually read, and how downloads are stored on the external volume.

The short version: **DwCA, ColDP, NEWICK, DOT**, in that order of preference.
The first is what nearly everything already here is in and what every importer
reads; the second is strictly better where it exists; the last two have no reader
at all yet. Details, traps and the measured inventory below.

---

## The preference

### 1. DwCA — Darwin Core Archive

The default, and not by accident: GBIF, ChecklistBank, Kew and the Species Files
all publish it, and it is the one shape our importers already open. Of the 39
archives on the volume, 28 are zips and all but four of those are DwCA or a
Species File export of one.

A DwCA is a zip carrying `meta.xml` (which names the core file in
`core/core.txt`) plus one or more delimited tables and an `eml.xml` metadata
block.

**The trap, measured on our own archives: DwC-A has two conventions for the core
file and they do not interoperate.** Older exports use `taxon.txt` — tab-separated
despite the extension — and newer ones use `Taxon.tsv`:

| core file | on the volume |
|---|---|
| `taxon.txt` | afromoths, aphid-species-file, orthoptera, afrotropical-bees, taiwan-endemic, all 15 `species-file-*` |
| `Taxon.tsv` | gbif-backbone (13,320 members), catalogue-of-life-2025 |
| neither | `wcvp` — a DwCA by `meta.xml`, but the tables are bespoke (`wcvp_taxon.csv`), so `portal/scripts/cacheWcvp.py` parses it by hand |

Writing a reader that assumes `Taxon.tsv` silently reads **nothing** from fifteen
of our own archives and fails with no error, because there is no file to open.
Resolve the core file from `meta.xml` rather than by name.

`taxonomicStatus` also varies by publisher and is a filter, not decoration: the
COL importers accept `accepted` and `provisionally accepted` and nothing else,
while `importAfromoths.py` exists precisely because Afromoths says `accepted` where
the Species Files say `valid`.

### 2. ColDP — Catalogue of Life Data Package

The same data model as a DwCA plus **per-name source attribution**, which is the
one thing a DwCA cannot give you. Where a publisher offers both, take ColDP.

That preference is not hypothetical: COL's DwCA export has 7 columns and no source
field, so every one of the 1,071,483 species we took from COL is recorded as
sourcedFrom `catalogue of life` rather than from the ~160 checklists beneath it.
A provenance loss we cannot reconstruct from the file we have. COL's ColDP export
currently 404s on GET, which is why we took the DwCA at all.

A ColDP-shaped archive has `NameUsage.tsv` (or `dataset-<id>.tsv`) and
`metadata.yaml` rather than a DwCA `meta.xml`. We already hold two:
`species-fungorum` (`dataset-2073.tsv`) and `world-spider-catalog`
(`NameUsage.tsv`), and **neither is read by anything here** — both are still on
the assessed list, so taking them was never the blocked step.

### 3. NEWICK — `.nwk`, `.tre`

**No reader in this repo.** No importer, no script, no sample file, nothing on
the volume.

NEWICK is a phylogeny, and this project's structure is a taxonomy:
`TaxonNode` has no field for branch lengths, no field for a supporting tree, and
the tree is assembled from `PHYLUM → CLASS → ORDER → FAMILY → … → SPECIES` at
build time. A phylogeny would need somewhere to live that is not a rank, which is
a design question rather than a parsing one.

Worth knowing when triaging a virus or prokaryote source: the obvious candidate,
ICTV, does not publish NEWICK. MSL is a spreadsheet —
`ICTV_Master_Species_List_2025_MSL41.v1.xlsx`, 1.72 MB, DOI
[10.5281/zenodo.19154110](https://doi.org/10.5281/zenodo.19154110), ratified
February 2026 — and the taxonomy is also browsable at `ictv.global/taxonomy`. So
the empty `sources/archives/ictv-msl/` directory is waiting on an xlsx, and the
xlsx is a fifth format this repo does not read either.

### 4. DOT — Graphviz

**No reader in this repo.** DOT is a graph description, not a data format, and
the portal renders its own graphs with D3 (`shared/src/components/FamilyTree.tsx`).
Its only plausible use here is a *rendered* phylogeny supplied by a publisher
instead of a NEWICK tree, which is strictly worse input: it is a picture of a
tree that has to be re-parsed, and it is the format most likely to have lost
branch lengths in the first place.

## How downloads are stored

```
/Volumes/MacieExternal/sources/
  archives/<slug>/<file>     immutable; the download as published
  work/<slug>/               derived, regenerable, safe to delete
  manifest.json              generated by scripts/sourcesManifest.py
```

`archives/` is never edited in place and `work/` is never an input, so clearing
`work/` costs disk-time and nothing else. Archive extensions follow the
publisher — 28 zip, 7 tgz, 3 gz, 1 xlsx — and `tar.gz` appears only where that is
all the publisher offers (AntWeb, BioImages, CalPhotos, FishBase, Flickr, NMNH,
msw3, Wikimedia Commons, USDA). Preferring zip is a convenience, not a rule:
every importer here reads a zip because a DwCA is a zip.

**Do not trust the extension.** ChecklistBank's `/dataset/<key>/archive.zip`
answers `content-type: application/zip` for every dataset and for ILDIS (1015)
returns a gzip'd tar anyway, so opening it as a zip raises `BadZipFile` on a
perfectly good download. `scripts/colChecklist.py` sniffs the two-byte magic
instead of going by the name.

**And do not trust one shape inside either.** Three datasets in a row, same
endpoint, same apparent format, three different schemas:

| dataset | columns | metadata | tables |
|---|---|---|---|
| reptile-db | bare snake_case (`parent_id`, `name_id`) | YAML inside a file called `Metadata.json` | COL's `Taxon`/`Name`/`Synonym` split |
| craneflies | `col:`-prefixed camelCase (`col:parentId`) | real JSON | same COL split |
| ildis | PascalCase (`AcceptedTaxonID`, `SpeciesEpithet`) | none at all | its own: `AcceptedSpecies.tsv`, `Synonyms.tsv`, `CommonNames.tsv`, … |

Two more traps in that family, both silent. `Name.tsv` carries no usable
`status` — all 34,366 reptile-db rows have it empty — so accepted-versus-synonym
has to come from `Synonym.tsv`. And the denormalised
`kingdom_name`…`family_name` columns are **empty in reptile-db and populated in
ILDIS**, so reading the chain from them without checking places nothing at all,
with no error to show for it.

Paths are resolved through `scripts/sources.py` / `scripts/paths.ts`, never
hardcoded, so an unmounted volume produces a sentence rather than an ENOENT.

Checksums are the point of the manifest. `--verify` recomputes sha256 for every
archive because **a truncated download reads as "this source has poor coverage"
rather than as an error**, which is a far more expensive thing to notice.

## The name index is a snapshot, and it is stale

`portal/data/name-parse-index.jsonl` (385 MB, gitignored) holds every species
name in the tree as of the moment it was written. Nothing in CI notices when it
drifts, and it drifts on every import. As of 2026-10-04 it is **19 hours old with
6,591 family files newer than it**, and it has been wrong in **both**
directions:

- Craneflies: 15,563 species scored new when 15,191 were already held.
- ILDIS: 13,347 of 16,371 species scored as already held when the tree holds 64.

The second is the expensive one — an importer trusting the index would have
skipped 13,283 species and reported success.

`make name-index-status` reports this and is wired into `make data` and
`make enrich`, so staleness surfaces on every build without costing anything.
`make name-index` rebuilds it, which is not a local reindex: `parseAllNames.py`
POSTs every name to GBIF's parser at roughly 113 names/s on one connection,
which is hours for the 2.4M names the tree now holds. Sharding brings that down
(`ARGS='--shard 0/6 --workers 6'`) but it cannot run inside a build.

Until it is rebuilt, the rule that survives both failures is: **stage everything
and let `merge_family` decide**, because it reads the file it is about to write
rather than a cached summary of every file. See the docstring of
`scripts/importColChecklist.py`, which was changed for exactly this.

39 archive directories, 37 of them indexed in `manifest.json`.

| shape | count | datasets |
|---|---|---|

| DwCA, `taxon.txt` | 18 | afromoths, aphid-species-file, orthoptera, afrotropical-bees, taiwan-endemic, 15 × `species-file-*` |
| DwCA by `meta.xml`, bespoke tables | 1 | wcvp |
| ColDP-shaped zip | 2 | species-fungorum, world-spider-catalog |
| DwCA-ish zip of CSVs | 1 | ictv-lists (304 members), eol-traitbank, zenodo-344329 |
| tar.gz | 7 | antweb, bioimages, calphotos, fishbase, flickr-eol, msw3, nmnh, wikimedia-commons, usda-plants |
| xlsx | 1 | mycobank |

**Five archive directories are not in the manifest at all**, which is the exact
failure the registry exists to prevent — a source that is not written down cannot
be cited:

| directory | state |
|---|---|
| `afrotropical-bees` | **registered 2026-10-04** — CC BY 4.0 read out of the archive's own eml.xml. Had 7,082 species in the tree stamped `sourcedFrom: "afrotropical bees"` with no registry entry at all |
| `msw3` | **registered 2026-10-04, status refused** — Mammal Species of the World is all rights reserved, copyright 2005 Johns Hopkins University Press. Nothing derives from it and nothing should |
| `iczn-lists` | **registered 2026-10-04, assessed** — CC0. The freely reusable nomenclatural authority, which ZooBank is not |
| `taiwan-endemic` | **registered 2026-10-04, assessed** — CC0, narrow |
| `ictv-msl` | **still empty** — a download started and abandoned. The one thing still unregistered, because there is nothing to register |

All four archives had been sitting on the volume unrecorded. Three were merely
untriaged, but `afrotropical-bees` was the failure this file is arguing about:
data in the product, licence recorded nowhere.

## When triaging a new source

1. Ask for the **DwCA** unless the publisher also offers **ColDP**, in which case
   take ColDP and accept the extra work — per-name provenance compounds.
2. Check what the core file is actually called before writing a reader, and
   resolve it from `meta.xml` rather than guessing `Taxon.tsv`.
3. Check `taxonomicStatus` values against what the importer accepts.
4. If it arrives as a **tree**, that is NEWICK or DOT and nothing here reads
   either. Take the file, register it as assessed, and say plainly that taking it
   means writing the reader — do not let a download imply a capability.
5. If it arrives as a **spreadsheet** (ICTV does), that is a fifth unsupported
   format, and `mycobank`'s xlsx shows even the supported-format rule does not
   cover what publishers actually send.
6. Register it in `scripts/sourcesManifest.py` with the licence and a verdict
   *before* importing, not after. An unregistered archive is invisible to
   `manifest.json --verify`, which is the check that catches a truncated download.
